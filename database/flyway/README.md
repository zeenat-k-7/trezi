## Important implementation rules

1. Flyway is the source of truth. Do not manually create or modify tables after migration.
2. Do not edit an already-applied migration. Add a new migration for schema changes.
3. The application uses UUID identifiers generated by PostgreSQL.
4. Timestamps are TIMESTAMPTZ and stored in UTC.
5. Money uses NUMERIC(15,2); investment quantity uses NUMERIC(20,8).
6. PostgreSQL native ENUM types are intentionally avoided. Application enums are represented using VARCHAR + CHECK constraints.
7. RAG embeddings use vector(1536), cosine distance, and an HNSW index.
8. Python AI service must not receive unrestricted PostgreSQL credentials.
9. React never connects directly to PostgreSQL or Gemini.
10. Do not seed real users, passwords, API keys, or financial data through migrations.
11. `ai_evidence` requires exactly one evidence source: a knowledge chunk OR a structured financial-data record.
12. `reasoning_traces` is an auditable summary, not private chain-of-thought.
13. Audit logs deliberately use `ON DELETE SET NULL` for the user reference so audit records are not silently removed by account deletion.
14. User-owned operational data uses controlled cascading deletes.
15. Regulatory/knowledge data is independent of users and is not deleted when a user account is deleted.

## Required environment configuration

Spring Boot / Flyway should receive the database URL and migration credentials through environment or secret management.

Do not commit database passwords, JWT secrets, Gemini keys, or service secrets to source control.

## Validation after migration

Run:

    SELECT version, description, success
    FROM flyway_schema_history
    ORDER BY installed_rank;

Then verify:

    SELECT extname FROM pg_extension
    WHERE extname IN ('pgcrypto', 'vector');

And:

    SELECT indexname
    FROM pg_indexes
    WHERE tablename = 'knowledge_chunks';

The expected vector index is:

    ix_knowledge_chunks_embedding_hnsw

## Deliberate non-features

The schema does not contain:

- investment transaction execution
- bank-account integration
- payment execution
- autonomous trading
- separate agent tables
- separate embeddings tables
- separate HyDE tables
- a separate retrieval-results table
- a separate verification table
- a tax-specific table
- fake/demo production users

Those are application/runtime concerns or future extensions, not part of the frozen MVP relational model.
